# CloudPush115 1.8.2

MoviePilot V2：本地扫描、事件实时监控、失败重试和 qB 下载完成后 SHA1 秒传。默认保留原文件。插件设置可在宿主原生表单或 Vue 配置页中完成，路径均填写 MP 容器内的绝对路径。

## 监控与处理流程

- `watch_paths` 是可读的监控源目录，例如 `/a/c`；多个目录按行填写。`realtime_enabled` 开启事件监控后，文件事件会先进入队列，等待 `realtime_settle` 秒（最小 1 秒）再进入稳定性检查。事件入队耗时只表示事件被接收和排队，不包含 SHA1 哈希计算或网络传输时间。
- 开启实时监控后接收 MoviePilot 的媒体、字幕和音频整理完成事件（以宿主支持为准），每秒唤醒一次轻量待办检查，不每秒遍历目录。原生 watchdog 可用时同时监控创建、移入和修改；不可用时保留整理事件和定期补扫。`scan_interval` 为分钟级补扫间隔。事件到来后等待并复查文件稳定，首次处理约需两次稳定等待，另加 SHA1 和网络耗时。
- `protected_paths` 是只读的源目录列表，例如 `/a/a`，每行一个目录。成功后的清理会保留受保护源目录中的原文件，只处理插件明确管理的链接。典型流程是 `/a/a` 保存源文件、`/a/c` 作为监控或管理链接目录，`/a/b` 作为可选失败链接目录。

## 文件副作用与硬链接安全

- `failure_move_enabled` 默认关闭。`failure_action=move` 时，`failure_move_dir` 是失败归档目录；`failure_action=hardlink` 时，会在该目录创建额外硬链接并保留监控路径 `/a/c`。硬链接模式要求失败目录与源文件位于同一文件系统，不会在跨文件系统时回退为复制。
- `failure_move_on=each_failure`：首次失败归档，后续沿归档路径重试，不重复改名移动。适用于无限重试。
- `failure_move_on=exhausted`（默认策略）：达到配置的最大重试次数后归档；启用时必须设置有限次数。qB 按文件失败次数判断动作时机，其重试由种子 watcher 继续管理。
- `delete_on_success` 默认关闭。只有明确成功、结果及动作意图持久化后才清理，并再次复核大小、mtime、设备和 inode。文件变化则保留；本地动作异常独立记录，远端 success 不变。
- `hardlink_only` 默认关闭。开启后，任何成功清理都要求目标是插件管理的硬链接且 `nlink >= 2`；不满足条件时保留源文件，避免误删唯一 inode。管理链接清理不会删除受保护源路径 `/a/a`。
- 网络或登录错误也算失败，远端结果可能未知；未明确成功绝不删除。明确未命中且关闭未命中重试的跳过项不移动、不删除。
- 失败移动或成功清理会影响 qB 做种，请仅在接受这一影响时启用。异常保留源文件。远端已成功但本地清理中断时，启动或下一次后台任务会恢复登记链接的清理，不重复提交远端秒传；仍需当前启用成功删除。只读索引不会触发清理。

只处理普通文件，拒绝软链。同名冲突生成唯一名称，绝不覆盖。同盘动作使用 no-overwrite link/unlink；跨盘的移动模式顺序复制到独占临时文件，fsync 并复读校验摘要、复核源签名后发布和删源。硬链接模式没有复制回退。

## 机械盘 SHA1

4 MiB `readinto` 可复用缓冲；支持时设置顺序读取建议。2048 项内存 LRU，键含路径、设备、inode、大小和纳秒修改时间。相同文件并发计算只读一次；两插件在同一 Python 进程共享缓存、同设备读锁与文件动作锁，减少重复读及同设备交错读。自动插件在自身数据目录的 `sha1-cache-v1.sqlite3` 保存最多 2048 项 SHA1，重启后校验路径、设备、inode、大小、mtime_ns、ctime_ns 后复用；数据库不可写或损坏时回退读取文件。内存缓存不跨进程；不同分区属于同一物理盘的情况不作拓扑识别。

首次 SHA1 仍需完整读取文件，受机械盘吞吐限制，不承诺倍速。回归使用临时文件和 fake 115/qB，验证摘要一致、只读一次及文件动作安全；没有访问真实网盘、种子服务或用户文件。

## 这套硬链接流程的配置

| 设置 | 示例值 |
|---|---|
| 本地监控目录 | `/a/c` |
| 受保护的源目录 | `/a/a` |
| 启用事件实时监控 | 开 |
| 事件稳定等待 | 2 秒 |
| 失败文件动作 | 创建额外硬链接并保留原路径 |
| 失败文件目录 | `/a/b` |
| 失败动作时机 | 每次失败 |
| 最大重试次数 | 0（不限） |
| 失败重试间隔 | 600 秒（可调，最小 30 秒） |
| 仅允许硬链接删除 | 开 |
| 秒传明确成功后删除 | 开 |

所有路径都使用 MP 容器内的实际路径。建议整个 `/a` 统一挂载，`/a/c` 与 `/a/b` 必须支持相互创建硬链接。上述示例需用户填写；升级不会自动填路径或开启失败动作、成功删除。

## 1.8.1 响应兼容修复

对照 `g-steven037/MoviePilot-Plugins` 的 `p115rapidretry/rapid.py`（通过 `upload_file_init` 及区间读取回调调用 p115client）与 `ChenyangGao/p115client` 的 `modules/p115cipher/p115cipher/util.py`。后者 PyCryptodome 分支仅解密响应中的完整 AES 块。当前插件在 ECDH 传输层对齐这一行为，直接 AES 原语仍拒绝非16字节对齐密文；解压后的 JSON 必须完整有效，绝不按片段推断成功。新增 `parser=3`、`remainder` 无敏感诊断。

日志 `wire=220` 和 `wire=236` 都余12字节，旧版在 AES 长度检查即失败；相同长度的合成响应已加入回归。没有用户原始响应，尚不能认定全部实际故障已排除。qB下载源直传和MP整理后监控为独立入口；仅要处理整理后 `/a/b` 时应关闭qB联动、源目录 `/a/a` 保护保留。
