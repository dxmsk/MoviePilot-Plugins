# 115网盘秒传 · MoviePilot V2

当前版本：**1.6.0**。

将 MoviePilot 容器可见的本地媒体文件，通过 SHA1 快传登记到 115 网盘。只读取源文件和校验区间，不移动、修改或删除源文件，不上传文件本体。首次计算大文件 SHA1 仍需读取磁盘。

## 1.6.0 修复了什么

- 修复主面板“只有分页器，没有整理条目/待重试/目录数据”：V2 动态渲染器无条件提供默认插槽，覆盖了 `VDataTable` 内置表头和表体。改用显式 `VTable / thead / tbody`；手机使用对应的卡片列表。
- 插件详情、系统 Dashboard 和 `/status` 使用同一套状态快照。所有区块一直显示；无数据时说明原因，不再消失。
- 新增真正的**本地待处理文件队列**，区别于仅列出监控目录。显示待处理、处理中、缺 Cookie、目录不可读等状态。
- 成功/失败/跳过记录与 qB 等待日志分开保存，重复等待日志不再挤掉成功记录。
- 本地失败按原目标目录重试；达到次数上限仍保留记录，不会下一次扫描重新当新文件上传。目录解析失败不再偷偷改传网盘根目录。
- 记录、文件状态、重试队列使用单个一致性检查点保存；保留旧版存储键供核对。升级时读取旧记录与队列。只有处理标记、没有原结果明细的旧文件会单独标注，不伪造成功时间。
- qB 按 `torrents/files` 核对期望文件、完成进度、大小和稳定性；能区分首次观察、文件变化、文件不存在、权限和路径映射问题。失败按间隔重试，标签失败只补标签，不重复秒传已成功文件。
- 旧版手填目录字段存成数组的问题自动迁移为文本；“仅运行一次”复位完整保存配置。设置页不扫描目录、不访问115。

## 安装 / 升级

在 MoviePilot V2 插件市场添加自定义仓库：

```text
https://github.com/dxmsk/MoviePilot-Plugins
```

刷新插件市场，安装或更新 **115网盘秒传**（插件 ID `CloudPush115`）。代码目录是 `plugins.v2/cloudpush115`，不是 `plugins/115cloudpush`。

升级跨越旧模块结构后，重启一次 MoviePilot 使新模块被载入。**不需要卸载插件或清空配置/数据。**

提供的 zip 是源码备份，内含 `cloudpush115/`。手动安装时应复制到 MoviePilot Python 插件代码目录；`/config/plugins` 通常是插件数据目录，不要把两者混用。可在容器内通过 `app.plugins.__file__` 确认实际代码位置。

依赖使用 MoviePilot 已有的 FastAPI、APScheduler；115 加密与 qB 客户端实现保留在插件内，不新增外部115 SDK。

## 设置：网页 Cookie + 手填目录

只使用 **115网页 Cookie**，没有开放平台令牌、扫码按钮或目录树。

1. 在浏览器登录 `115.com`，从该站请求头复制包含 `UID / CID / SEID` 的 Cookie，填入插件设置。
2. 本地监控路径填 **MoviePilot 容器内**绝对路径；多个路径用换行或逗号分隔：

   ```text
   /media/电影
   /media/电视剧
   ```

3. 115目标目录例如 `/媒体/电影`。留空或 `/` 表示网盘根目录，缺失目录在秒传时创建。
4. 开启定时扫描后先执行一轮，再按设置的分钟间隔运行；也可以仅选“保存后立即运行一次”。

配置完成后会异步建立只读本地索引；未启用上传时也能看到待处理文件。

### 主页上的五个区块

| 区块 | 内容 |
|---|---|
| 整理条目 | 实际秒传成功、失败、跳过；文件、大小、原因、源路径、目标路径、时间 |
| 待重试队列 | 失败次数、下次时间、原目标、耗尽/阻塞状态 |
| 本地待处理队列 | 索引发现的待处理/处理中文件，不是只有目录名称 |
| qB联动任务 | 已完成种子的待稳定/处理/失败状态、就绪文件数、MP内路径和原因 |
| 本地监控路径 | 每个配置路径的索引状态、匹配数量、权限或挂载错误 |

- **插件详情页**：点击“刷新显示”在当前弹窗更新数据。原生详情渲染器没有自动轮询契约。
- **MoviePilot 系统首页 Dashboard**：在首页组件设置中启用“115秒传主面板”；首页活跃且启用自动刷新时每10秒更新。声明 Dashboard 不会修改用户首页组件选择。
- “刷新本地队列”只更新元数据；“扫描并秒传”执行本地传输；“重试失败文件”重新安排本地失败项。Dashboard 自身只显示数据，不放置宿主不会响应的按钮。
- 页面限制渲染数量以保持流畅，显示实际总数；详情最多100项/区块，Dashboard最多50项/区块。状态API支持分页。

### 重试语义

- `retry_interval` 最短30秒，默认600秒；普通扫描不会绕过这个间隔。
- `max_attempts=N` 表示初次失败后最多再重试 N 次；`0` 为不限。耗尽项保留供人工重试。
- 仅115明确返回 `status=1` 才判为未命中；未知状态、网络或鉴权错误不会冒充未命中。
- 文件去重同时检查路径、文件大小、`mtime_ns`、inode、115账号及目标目录。同路径文件被替换或目标改变后会重新识别。
- 115账号变更时旧重试任务保留并暂停，避免发到错误账号。

## qBittorrent 联动

qB 地址可手填，也可留空读取 MoviePilot V2 `app.helper.service.ServiceConfigHelper` 的有效下载器配置。

两个容器挂载不一致时，可填显式路径映射（每行一条，左边qB、右边MP）：

```text
/downloads=>/media/downloads
/downloads/movies=>/media/movies
```

按最长完整前缀匹配，不按文件名猜路径。

`就绪 0/1` 不等于秒传失败。原版把首次稳定观察、文件不存在和变化都写成同一句话；新版会显示具体原因。稳定判定比较大小、纳秒修改时间和inode；等待秒数为配置的完整值，设0则不额外等待。

仅当所有**选中的匹配媒体文件**都真实完成、稳定且秒传成功，才添加“已整理”标签。qB设置为不下载（priority=0）的文件不参与，并在任务状态中说明。无选中媒体文件时不打标签。失败保留给 MoviePilot 的正常整理流程，未成功不标记完成。

## API

统一前缀 `/api/v1/plugin/CloudPush115`，使用宿主 bearer 鉴权。

- `GET /status?limit=100&offset=0`：只读快照，可用 `section=history|local_queue|retry_queue|qb_queue` 取某个列表。
- `GET /refresh`：刷新页面事件，无文件/网络副作用。
- `POST /index`：只读本地索引。
- `POST /scan`：扫描并秒传。
- `POST /retry`：重新安排本地失败项，body 可含 `{"path":"/media/a.mkv"}`；不填为全部本地失败项。
- `POST /test`：检查已保存的115 Cookie。

旧目录树和扫码交互已撤下；这版不恢复它们。
